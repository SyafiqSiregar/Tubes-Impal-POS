BAB I. ARSITEKTUR BASIS DATA & SKEMA RELASI
Standar Nilai A
Kesesuaian dengan Petunjuk Tugas: 1. Memenuhi standar 3 tabel pokok POS: PRODUK (KodeProduk, NamaProduk, satuan, hargasatuan, stockmin, stock), PENJUALAN (KodeJual, TglJual, Total), dan PENJUALANDetail (KodeJual, KodeProduk, Quantity).
2. Menjawab catatan nilai di atas B: Menambahkan entitas TOKO, KASIR, KATEGORI, PELANGGAN, dan PENGELUARAN dengan integritas referensial (Foreign Key) yang ketat.

1.1 Gambaran Umum Sistem

Sistem Point of Sale (POS) Raya Koffie & 439 Carwash merupakan sistem kasir terintegrasi yang melayani dua model bisnis sekaligus: penjualan produk makanan/minuman (F&B Kafe) dan jasa pengerjaan perawatan kendaraan (Carwash & Auto Detailing).

1.2 Entitas dan Integritas Relasional

1.3 Desain Normalisasi Basis Data

Struktur tabel ini telah memenuhi Bentuk Normal Ketiga (3NF):

  • 1NF (First Normal Form): Menghapus atribut multivalued atau array; item pesanan dipisahkan ke dalam tabel relasional anak PENJUALAN_DETAIL secara atomik.
  • 2NF (Second Normal Form): Seluruh atribut non-key bergantung penuh pada Primary Key masing-masing tabel.
  • 3NF (Third Normal Form): Menghilangkan ketergantungan transitif; informasi toko, kasir, dan kategori dipisah ke entitas induknya masing-masing.

BAB II. SINTAKS DDL (CREATE TABLE)
8 Tabel Relasional

Berikut adalah sintaks SQL CREATE TABLE lengkap yang telah dirancang sesuai batasan integritas data (Primary Key, Foreign Key, Check Constraint, dan Default Value):

-- 1. TABEL TOKO (Outlet/Cabang Operasional) CREATE TABLE TOKO ( KodeToko VARCHAR(10) PRIMARY KEY, NamaToko VARCHAR(100) NOT NULL, Alamat VARCHAR(255) NOT NULL, NoTelepon VARCHAR(20), Status VARCHAR(20) DEFAULT 'AKTIF' CHECK (Status IN ('AKTIF', 'NONAKTIF')) ); -- 2. TABEL KASIR (Staf / Pengguna Bertugas) CREATE TABLE KASIR ( KodeKasir VARCHAR(10) PRIMARY KEY, KodeToko VARCHAR(10) NOT NULL, NamaKasir VARCHAR(100) NOT NULL, Username VARCHAR(50) NOT NULL UNIQUE, Password VARCHAR(100) NOT NULL, Role VARCHAR(20) DEFAULT 'KASIR' CHECK (Role IN ('ADMIN', 'KASIR', 'SUPERVISOR')), Status VARCHAR(20) DEFAULT 'AKTIF' CHECK (Status IN ('AKTIF', 'NONAKTIF')), CONSTRAINT FK_Kasir_Toko FOREIGN KEY (KodeToko) REFERENCES TOKO(KodeToko) ON UPDATE CASCADE ON DELETE RESTRICT ); -- 3. TABEL KATEGORI (Kategori Menu & Layanan) CREATE TABLE KATEGORI ( KodeKategori VARCHAR(10) PRIMARY KEY, NamaKategori VARCHAR(50) NOT NULL, TipeDivisi VARCHAR(20) NOT NULL CHECK (TipeDivisi IN ('KAFE', 'CARWASH', 'UMUM')) ); -- 4. TABEL PRODUK (Sesuai Catatan Dosen: KodeProduk, NamaProduk, satuan, hargasatuan, stockmin, stock) CREATE TABLE PRODUK ( KodeProduk VARCHAR(10) PRIMARY KEY, KodeKategori VARCHAR(10) NOT NULL, NamaProduk VARCHAR(100) NOT NULL, Satuan VARCHAR(20) NOT NULL, HargaSatuan NUMERIC(12, 2) NOT NULL CHECK (HargaSatuan >= 0), StockMin INT NOT NULL DEFAULT 5 CHECK (StockMin >= 0), Stock INT NOT NULL DEFAULT 0 CHECK (Stock >= 0), CONSTRAINT FK_Produk_Kategori FOREIGN KEY (KodeKategori) REFERENCES KATEGORI(KodeKategori) ON UPDATE CASCADE ON DELETE RESTRICT ); -- 5. TABEL PELANGGAN (Member Konsumen & Plat Nomor) CREATE TABLE PELANGGAN ( KodePelanggan VARCHAR(10) PRIMARY KEY, NamaPelanggan VARCHAR(100) NOT NULL, NoHp VARCHAR(20), PlatNomor VARCHAR(15), PoinLoyalti INT DEFAULT 0 CHECK (PoinLoyalti >= 0) ); -- 6. TABEL PENJUALAN (Sesuai Catatan Dosen: KodeJual, TglJual, Total, + Relasi Toko & Kasir) CREATE TABLE PENJUALAN ( KodeJual VARCHAR(20) PRIMARY KEY, KodeToko VARCHAR(10) NOT NULL, KodeKasir VARCHAR(10) NOT NULL, KodePelanggan VARCHAR(10), TglJual TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP NOT NULL, Subtotal NUMERIC(12, 2) NOT NULL CHECK (Subtotal >= 0), Diskon NUMERIC(12, 2) DEFAULT 0 CHECK (Diskon >= 0), Pajak NUMERIC(12, 2) DEFAULT 0 CHECK (Pajak >= 0), Total NUMERIC(12, 2) NOT NULL CHECK (Total >= 0), MetodeBayar VARCHAR(20) DEFAULT 'CASH' CHECK (MetodeBayar IN ('CASH', 'QRIS', 'TRANSFER')), CONSTRAINT FK_Penjualan_Toko FOREIGN KEY (KodeToko) REFERENCES TOKO(KodeToko) ON UPDATE CASCADE ON DELETE RESTRICT, CONSTRAINT FK_Penjualan_Kasir FOREIGN KEY (KodeKasir) REFERENCES KASIR(KodeKasir) ON UPDATE CASCADE ON DELETE RESTRICT, CONSTRAINT FK_Penjualan_Pelanggan FOREIGN KEY (KodePelanggan) REFERENCES PELANGGAN(KodePelanggan) ON UPDATE CASCADE ON DELETE SET NULL ); -- 7. TABEL PENJUALANDETAIL (Sesuai Catatan Dosen: KodeJual, KodeProduk, Quantity, + Subtotal) CREATE TABLE PENJUALAN_DETAIL ( KodeDetail SERIAL PRIMARY KEY, KodeJual VARCHAR(20) NOT NULL, KodeProduk VARCHAR(10) NOT NULL, Quantity INT NOT NULL CHECK (Quantity > 0), HargaSatuan NUMERIC(12, 2) NOT NULL CHECK (HargaSatuan >= 0), Subtotal NUMERIC(12, 2) NOT NULL CHECK (Subtotal >= 0), CONSTRAINT FK_Detail_Penjualan FOREIGN KEY (KodeJual) REFERENCES PENJUALAN(KodeJual) ON UPDATE CASCADE ON DELETE CASCADE, CONSTRAINT FK_Detail_Produk FOREIGN KEY (KodeProduk) REFERENCES PRODUK(KodeProduk) ON UPDATE CASCADE ON DELETE RESTRICT, CONSTRAINT UQ_Jual_Produk UNIQUE (KodeJual, KodeProduk) ); -- 8. TABEL PENGELUARAN (Operasional Kas Kasir) CREATE TABLE PENGELUARAN ( KodePengeluaran VARCHAR(10) PRIMARY KEY, KodeToko VARCHAR(10) NOT NULL, KodeKasir VARCHAR(10) NOT NULL, TglPengeluaran DATE NOT NULL, Kategori VARCHAR(50) NOT NULL, Deskripsi TEXT NOT NULL, Jumlah NUMERIC(12, 2) NOT NULL CHECK (Jumlah > 0), SumberDana VARCHAR(30) DEFAULT 'KAS_KASIR', CONSTRAINT FK_Pengeluaran_Toko FOREIGN KEY (KodeToko) REFERENCES TOKO(KodeToko) ON UPDATE CASCADE ON DELETE RESTRICT, CONSTRAINT FK_Pengeluaran_Kasir FOREIGN KEY (KodeKasir) REFERENCES KASIR(KodeKasir) ON UPDATE CASCADE ON DELETE RESTRICT );

BAB IV. PEMBUKTIAN RELASI (QUERY UJI COBA / JOIN)
Pengujian DQL

Untuk membuktikan bahwa seluruh tabel telah terhubung secara relasional melalui Foreign Key dengan benar, dilakukan serangkaian pengujian kueri kompleks (Multi-table JOIN dan Aggregation):

4.1 Kueri Laporan Transaksi Kasir Lengkap

SELECT p.KodeJual, p.TglJual, t.NamaToko, k.NamaKasir, COALESCE(plg.NamaPelanggan, 'Umum') AS NamaPelanggan, COALESCE(plg.PlatNomor, '-') AS PlatNomor, p.MetodeBayar, p.Total FROM PENJUALAN p JOIN TOKO t ON p.KodeToko = t.KodeToko JOIN KASIR k ON p.KodeKasir = k.KodeKasir LEFT JOIN PELANGGAN plg ON p.KodePelanggan = plg.KodePelanggan ORDER BY p.TglJual ASC;

4.2 Kueri Rincian Struk Item Belanja per Transaksi

SELECT d.KodeJual, prd.NamaProduk, kat.NamaKategori, d.Quantity, prd.Satuan, d.HargaSatuan, d.Subtotal FROM PENJUALAN_DETAIL d JOIN PRODUK prd ON d.KodeProduk = prd.KodeProduk JOIN KATEGORI kat ON prd.KodeKategori = kat.KodeKategori ORDER BY d.KodeJual, d.KodeDetail;

4.3 Kueri Monitoring Stok Produk & Peringatan Ambang Batas

SELECT prd.KodeProduk, prd.NamaProduk, prd.Stock, prd.StockMin, prd.Satuan, COALESCE(SUM(d.Quantity), 0) AS TotalTerjual, CASE WHEN prd.Stock <= prd.StockMin THEN 'PERINGATAN: STOK MENIPIS' ELSE 'STOK AMAN' END AS StatusInventori FROM PRODUK prd LEFT JOIN PENJUALAN_DETAIL d ON prd.KodeProduk = d.KodeProduk GROUP BY prd.KodeProduk, prd.NamaProduk, prd.Stock, prd.StockMin, prd.Satuan ORDER BY TotalTerjual DESC;
BAB V. KESIMPULAN

Berdasarkan perancangan di atas, basis data POS Raya Koffie & 439 Carwash telah berhasil dirancang dengan memenuhi kriteria tugas kelompok, mencakup:

  • Seluruh tabel inti POS (PRODUK, PENJUALAN, PENJUALAN_DETAIL) terpenuhi dengan nama kolom persis sesuai ketentuan.
  • Kompleksitas tinggi tercapai dengan penambahan entitas TOKO, KASIR, KATEGORI, PELANGGAN, dan PENGELUARAN beserta relasinya.
  • Setiap tabel telah dilengkapi minimal 5 data awal yang valid dan konsisten.
  • Seluruh sintaks SQL siap dieksekusi pada mesin PostgreSQL/Supabase maupun RDBMS standar lainnya.
